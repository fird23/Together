# Together — запуск и обновление

## Что изменилось в этой версии

- Сценарий теперь такой: **регистрация → выбор «Создать пару» / «У меня есть приглашение» → дата (только при создании) → ссылка партнёру → общее пространство**.
- Отдельные страницы: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/couple`, `/couple/new`, `/invite/[token]`, `/dashboard`, `/profile`, `/settings`.
- Страница приглашения показывает все состояния: действительное, истёкшее, использованное, отменённое, «своё», «вы уже в паре».
- Можно отменить приглашение, выпустить новое и расформировать пару (с подтверждением вводом слова).
- Новая миграция базы: `supabase/migrations/002_onboarding_and_invitations.sql`.

## Что нового в версии 4 (миграций базы нет)

- **Оформление.** Тёмная тема и пять цветовых тем: Гортензия (по умолчанию, палитра с вашего фото), Роза, Шалфей, Закат, Океан. У каждой есть светлая и тёмная версии. Быстрый переключатель светлой/тёмной темы есть в шапке, полный выбор: **Настройки → Оформление**. Режим «Как в системе» следует за темой телефона или компьютера.
- **Новая главная:** счётчик, «Ближайшие даты» (1000 дней, годовщины, полгода) и сводка «Ваш путь».
- План остальных функций: [PLAN.md](./PLAN.md).
- Обновление: замените `src`, `supabase`, `package.json`, `package-lock.json`, `PLAN.md`, `SETUP.md`, `README.md` файлами из архива, выполните `npm install`, затем `git push`. В Supabase ничего запускать не нужно.
- Выбранная тема хранится в браузере, поэтому на новом устройстве её нужно выбрать заново.

## Что нового в версии 3

- **Фото профиля.** На странице «Профиль» можно добавить, заменить и удалить фото. Браузер сам обрезает его по центру до квадрата 512×512 и сжимает (учитывается поворот с телефона), партнёр видит новое фото сразу.
- Новая миграция базы: `supabase/migrations/003_avatars.sql` (хранилище файлов и правила доступа).

## Как обновить проект с версии 2 (если уже ставили её)

1. Замените `src`, `supabase`, `package.json`, `package-lock.json` файлами из архива (как в инструкции ниже). Новых пакетов нет, `npm install` всё равно выполните.
2. Supabase → SQL Editor → New query: вставьте `supabase/migrations/003_avatars.sql` → Run. Миграцию 002 повторять не нужно.
3. Проверьте: Storage → должен появиться бакет `avatars` (Public).
4. `git add .`, `git commit -m "Фото профиля"`, `git push`.

## Как обновить уже работающий проект (с версии 1)

1. Остановите `npm run dev` (Ctrl+C).
2. В папке проекта **удалите** `src`, `supabase`, `package.json`, `package-lock.json`.
   Не трогайте `.git`, `.env.local`, `node_modules`.
3. Скопируйте из архива в папку проекта: `src`, `supabase`, `public`, `package.json`, `package-lock.json`, `SETUP.md`, `README.md`, `.env.example`.
4. В терминале, в папке проекта: `npm install`.
5. **Supabase → SQL Editor → New query:** по очереди выполните
   `supabase/migrations/002_onboarding_and_invitations.sql`, затем `supabase/migrations/003_avatars.sql`
   (вставить содержимое и нажать **Run**). `schema.sql` повторно запускать не нужно: он нужен только для установки с нуля.
6. **Supabase → Authentication → URL Configuration → Redirect URLs.** Добавьте обе строки
   (с `/**` на конце, чтобы подошли все страницы):
   - `http://localhost:3000/**`
   - `https://АДРЕС-ВАШЕГО-САЙТА.vercel.app/**`
7. `npm run dev` и откройте http://localhost:3000.
8. Для публикации: `git add .`, `git commit -m "Новый сценарий пары"`, `git push`. Vercel соберёт сайт сам.
   Переменные окружения на Vercel менять не нужно.

## Установка с нуля

1. Создайте проект на https://supabase.com/dashboard.
2. Project Settings → API: скопируйте Project URL и anon/publishable key в файл `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_ANON_OR_PUBLISHABLE_KEY
```

Не кладите ключи `service_role` / `secret` в переменные `NEXT_PUBLIC_*`.

3. SQL Editor: выполните весь файл `supabase/schema.sql`.
4. Authentication → URL Configuration: добавьте адреса из пункта 6 выше.
5. `npm install`, затем `npm run dev`.

## Подтверждение email

Приложение работает в обоих режимах (Authentication → Providers → Email → Confirm email):

- **Включено:** после регистрации показывается «Проверьте почту». После перехода по ссылке человек попадает в приложение (или на страницу приглашения, если регистрировался по ссылке).
- **Выключено:** после регистрации сразу открывается выбор «Создать пару / У меня есть приглашение».

Встроенная почта Supabase отправляет лишь несколько писем в час. Для постоянной работы подключите свой SMTP (например, Resend): Authentication → SMTP Settings.

## Проверка вдвоём

1. Окно 1: зарегистрируйте аккаунт A, нажмите «Создать пару», укажите дату, скопируйте ссылку.
2. Окно 2 (режим инкогнито или другой браузер): откройте ссылку, нажмите «Создать аккаунт и принять», зарегистрируйте B, нажмите «Принять приглашение».
3. Оба аккаунта видят общую страницу и один и тот же счётчик.

## Безопасность

- Токены приглашений случайные (32 байта), в базе хранится только SHA-256-хеш.
- Все операции с приглашениями идут через функции базы с блокировкой: два человека не смогут занять одно место одновременно.
- Данные пары защищены политиками RLS: посторонний не видит чужую пару, участников и профили.
- Email в профиле нельзя изменить из браузера; приглашения нельзя читать и менять напрямую.
- Фото: загрузить файл можно только в свою папку и только `.jpg/.png/.webp` до 1 МБ. В профиль записывается лишь путь внутри этой папки, внешнюю ссылку база не примет (иначе она загружалась бы у партнёра и выдавала его IP).
- Хранилище фото публичное: любой, у кого есть точная ссылка, может открыть картинку. Ссылку нельзя угадать (в ней идентификаторы), но не загружайте как фото профиля ничего, что нельзя показывать посторонним.

## Что пока не входит

Галерея, календарь и воспоминания.


## Трекер привычек

После обновления проекта выполните SQL-миграцию `supabase/migrations/004_habits.sql` в Supabase Dashboard → SQL Editor. Она создаёт таблицы привычек и отметок, индексы и RLS-политики. Общие привычки видны обоим участникам пары; личные и их отметки доступны только владельцу. Отметки сохраняются отдельно для каждого участника.


## Новые функции главной страницы

Главная страница обновлена: компактный счётчик отношений расположен рядом с календарём; далее выводится полный блок привычек (создание, личные/общие привычки, отметки выполнения, серии, переименование и удаление), ниже — ежедневный выбор настроения с заметкой для партнёра.

После обновления примените SQL в Supabase Dashboard → SQL Editor в таком порядке:
1. `supabase/migrations/004_habits.sql` — таблицы, RLS и права на переименование привычек.
2. `supabase/migrations/005_mood.sql` — ежедневные отметки настроения и политики доступа.

Если миграция 004 уже применялась ранее, её можно запустить повторно: политики создаются с предварительным удалением одноимённых политик.


## Изменения главной страницы и вишлисты

- Календарь в верхней части главной уменьшен, показывает фиксированную сетку из шести недель (при смене месяца карточка не меняет высоту и расположение). По ссылке «Открыть календарь» доступна отдельная страница `/calendar` с выбором даты и переходом к сегодняшнему дню.
- Счётчик «Мы вместе уже» сделан компактнее, декоративные пересекающиеся круги убраны. Блок настроения перенесён в компактную карточку слева от счётчика и под календарём.
- Под привычками появился раздел «Вишлисты»: личный список желаний, список партнёра, добавление и удаление своих пунктов, отметка желаний партнёра как исполненных.

Для вишлистов выполните новую миграцию `supabase/migrations/006_wishlist.sql` в Supabase Dashboard → SQL Editor. Миграции 004 и 005 повторно выполнять не нужно, если они уже применены.
